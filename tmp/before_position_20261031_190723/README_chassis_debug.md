# F103 四轮麦轮底盘调试

适用工程：`MDK-ARM/car_code1.uvprojx`，STM32F103RCT6，X42S / Emm 固件，X 型麦轮。

电机驱动器内部已实现编码器闭环。STM32 发送目标转速，不需要先在 STM32 上重写电机轴的 PID。内部闭环不等于整车定位闭环；轮子打滑、安装偏差造成的偏航，仍需要后续用 IMU、视觉等反馈纠正。

## 接线与菜单

四台电机共用一条 CAN 总线和一个 TJA1050 收发器：CANH 全部相连，CANL 全部相连，使用主干加短支线连接。总线两个物理末端各一个 120Ω 电阻，确认已有终端电阻后再决定是否外加。普通非隔离接法需主控、收发器、电机电源负极共地。

- TJA1050 TX/TXD → PA12（CAN_TX），RX/RXD → PA11（CAN_RX）。
- 电机供电 12V；TJA1050 按模块规格供电，普通 TJA1050 使用 5V，不能把 12V 直接接其 VCC。
- KEY0 接 PC5，按下低电平，程序配置内部上拉并进行 30ms 消抖。
- 四个电机均设 `FWType=FW_Emm`、`CtrlMode=CR_VFOC`、`P_Serial=CAN1_MAP`、`CAN_Baud=500000`、`Checksum=0x6B`。
- **`Response=Receive` 或 `Both`，`S_Vel_IS=Disable`。** 本程序会等待动作应答；设为 None 或 Reached 会报应答超时。
- 电机须完成编码器校准；排除低压、堵转等告警。本程序不会自动校准或自动清除保护。

从车顶俯视，车头朝前：

| 数组索引 | 轮位 | 电机地址 | 默认 forward_sign |
|---|---|---|---|
| 0 | 左前 FL | 1 | +1 |
| 1 | 右前 FR | 2 | -1 |
| 2 | 左后 RL | 4 | +1 |
| 3 | 右后 RR | 3 | -1 |

默认方向只是对左右镜像安装的初始假设，必须实测。

## 烧录与 KEY0 操作

1. 打开上述 Keil 工程，编译并下载。也可以使用 `MDK-ARM/car_code1/car_code1.hex`。
2. 四轮先架空，四台电机都连接并供电。**即便做单轮测试，本版本也检查全部四台的应答。**
3. 上电后等待约 1 秒，程序发送停车命令，等待按键，不会自动试转。
4. 每次短按并松开 KEY0，执行下一项。默认目标为电机轴 **20 RPM**，运行约 **1 秒**后发立即停止指令，保持使能。
5. 运行中再次按下 KEY0，消抖后发停车命令；松开不会立即开始下一项。按键停止和定时停止都依赖 MCU 正常运行与 CAN 链路可用；断开 CAN 或暂停调试器不能保证电机停止。

| 测试项 | 动作 |
|---|---|
| 1 | 左前，地址 1，前进方向 |
| 2 | 右前，地址 2，前进方向 |
| 3 | 左后，地址 4，前进方向 |
| 4 | 右后，地址 3，前进方向 |
| 5 | 整车前进 |
| 6 | 整车后退 |
| 7 | 整车左横移 |
| 8 | 整车右横移 |
| 9 | 俯视逆时针旋转 |
| 10 | 俯视顺时针旋转，然后回到第 1 项 |

四个单轮测试成功后，下一项为 5。此时默认仍禁止整车运动：

- 确认四轮都向“使车前进”的方向转动。可观察轮子**顶部朝车头运动，底部朝车尾运动**，不要仅比较四个电机看起来是 CW 还是 CCW。
- 若某轮反向，修改 `Core/Inc/chassis_debug.h` 中该轮的 `CHASSIS_*_FORWARD_SIGN`，将 `+1` 与 `-1` 对调，重新编译烧录，再测四轮。
- 四轮方向正确后，**在第 5 项前长按 KEY0 至少 2 秒再松开**，确认方向并解锁。这一步不运动；再次短按才开始前进测试。
- 解锁保存在 RAM，重新上电需重新确认。全部验证完成后，可把头文件中的 `CHASSIS_DIRECTIONS_CONFIRMED` 改成 `1U`，再编译烧录。
- 在其他状态长按至少 800ms，停车并将下一项重置为 1。第 5 项未解锁时的长按专用于确认方向。

如果没有反应，不要连续跳过：连接 Keil 查看下述故障变量。当前版本未接入指示灯或串口提示。

## Keil 观察变量

### KEY0 没反应时先确认程序在运行

2026-10-31 检查发现 CubeMX 重新生成后的工程启用了 `CAN1_RX1_IRQn`，而滤波器、通知和回调仍使用 FIFO0，导致收不到电机应答。已恢复为 `USB_LP_CAN1_RX0_IRQn`，并同步修正 `.ioc`。以后生成代码时确认 CAN RX0 已勾选。

若 `chassis_debug.address` 不是 `1,2,4,3`，或 `rpm`、`state` 显示巨大随机数，不能把这些值当作有效的运行状态。先退出调试、Rebuild、Download 并确认下载校验成功；进入调试后按 F5，等待约 2 秒。停在 Reset_Handler、SystemInit 或 C 运行时初始化之前时，RAM 里的全局变量尚未有效。若已到 main 仍是随机值，检查本次 AXF 符号与烧录程序是否对应、BOOT0 是否为低电平；仍异常则需要查看实际停机位置和寄存器，不要手工把整组随机值改成正常值来掩盖问题。

新增 Watch 项：

| 变量 | 正常现象 |
|---|---|
| `app_boot_stage` | 最终为 9，表示 CAN、等待和按键任务初始化已完成 |
| `app_error` | 0；1 表示进入 Error_Handler，boot_stage 保留失败前阶段 |
| `chassis_task_count` | 主循环运行时持续增加 |
| `chassis_task_tick` | 主循环读取到的毫秒 tick，持续增加 |
| `key0_level` | 松开为 1，按住为 0；在主循环运行时刷新 |
| `key0_press_count` | 每次有效按下（消抖 30ms）增加 1 |

正常初始化后，短按并松开 KEY0 才启动单轮测试。`trigger` 增加但没有转动时，查看下面的 `fault`、`fault_address`。测试要求四台电机都有应答；只接一台时会在其余电机地址处报错。程序暂停时不会扫描按键，观察按住电平可先 F5 运行，再按住 KEY0 后暂停查看；此操作应在底盘架空且未开始运动时进行。

`chassis_debug` 中的参数可在停车状态修改：

- `rpm`：默认 20，允许 1～60 RPM。
- `duration_ms`：默认 1000，允许 1～3000ms。
- `next_test`：下一次短按执行的项目，1～10。
- `forward_sign[4]`：运行时方向修正，顺序为左前、右前、左后、右后。
- `mapping_confirmed`：1 表示已确认轮位、方向及 X 型安装。
- `state`：0 空闲，1 运行，2 故障。
- `fault_address`：发生故障的 CAN 地址，0 通常表示配置问题。
- `target_rpm[4]`：按“轮子前进为正”表示的目标；与电机协议原始正负号可能不同。

| fault | 意义 | 排查 |
|---|---|---|
| 0 | 无故障 | — |
| 1 | 参数错误或未确认方向 | 检查方向开关、地址、速度和测试时长 |
| 2 | CAN 发送失败或超时 | 接线、收发器供电、终端电阻、500k 波特率 |
| 3 | 动作应答超时或电机拒绝 | 查 `motor_feedback[地址].ack_status`，检查 Response 菜单及告警 |
| 4 | 电机失能、堵转或堵转保护 | 检查 `motor_feedback[地址].flags` 与电机显示屏 |
| 5 | 状态反馈超时 | 检查对应地址电机是否掉电或掉线 |

`motor_feedback[1..4]` 按**地址**索引：`speed_rpm` 是电机原始带符号转速，`speed_tick` 是最后速度反馈时间，`flags_tick` 是最后状态反馈时间。状态位和速度轮询每 50ms 换一个电机，每个电机约 200ms 更新一次。

`command=0` 可在程序运行时请求停车。手动指定动作时，先填 `command=1..10`，最后递增 `trigger`。**不要在电机转动时让 Keil 暂停程序**，软件计时停车也会暂停。

## 当前代码范围

- 增加 `chassis_debug.c/.h`：按键测试、轮位映射、方向修正、X 型轮速混合、超时和故障处理。
- `main.c` 改为上电停车与按键任务。
- 配齐 CAN FIFO0 滤波器、通知、NVIC 和 `USB_LP_CAN1_RX0_IRQHandler`。
- CAN 发送从无限重试改为限时等待，逐帧确认发送完成；解析单帧使能/速度/停止应答与状态、速度反馈。
- `.ioc` 同步保存 PC5 上拉输入与 FIFO0 中断设置；Keil 工程已加入新源文件。
- 初期采用逐台发送并确认，四轮启动存在数毫秒偏差。尚未做同步触发、车速物理单位换算、里程计、IMU 纠偏和比赛任务状态机。
- 麦轮混合定义：前进、左移、逆时针为正；轮序 FL/FR/RL/RR。输入目前是电机 RPM 的分量，后续换算 m/s、rad/s 需要轮径、轴距、轮距和减速比。

## 验证

Keil ARMCC 5 编译。工程原有 `fifo.c/.h` 和 `delay.c/.h` 的缺少末尾换行警告与本次功能无关。

`tests/host/` 用替代 HAL 编译**实际 chassis_debug.c**，验证启动不运动、按键消抖、轮位与方向、六种整车轮速、按键停止、单次执行、计时停止、方向确认、缺失或拒绝应答、反馈超时、重复地址和堵转处理。运行：

```powershell
powershell -ExecutionPolicy Bypass -File tests/host/build_and_test.ps1
```

这些是软件行为测试，不验证实物接线、收发器电气特性、轮子实际方向和地面运动效果。最终需要按上面的四轮架空顺序实测。
