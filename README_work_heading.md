## 朝向约定

麦轮底盘可以保持任意车头朝向沿地图路线平移；主控将地图位移投影到当前车体前/左方向。因此作业后不需要先转回启动方向，本次实现保持上一站朝向行驶，到下一工作站再调整朝向。

所有工作角度都相对于路线上传的 **initial_pose.yaw_deg（初始地图航向）**，不是相对于刚到站时的方向，也不是IMU开机读数。每次到站求绝对目标，不累计加90度。初始地图航向必须与实车摆放方向一致。

| 区域 | work_id | 相对启动航向 | 起始航向90°时的绝对地图航向 |
|---|---|---|---|
| 二维码 | 101 | 逆时针90° | 180°（状态可能显示−180°，方向相同） |
| 原料，两次 | 102、105 | 顺时针90° | 0° |
| 粗加工，两次 | 103、106 | 逆时针90° | 180° |
| 暂存，两次 | 104、107 | 0° | 90° |
| 回启停区 | 108 | 0° | 90° |

回启停区默认恢复启动朝向。下一站相对当前车头的转角由目标绝对航向之差求得，例如二维码→原料可能需要转约180°，不会只转90°。采用最短角差，恰好180°默认逆时针；由于实际停转有小误差，接近180°时也可能选择顺时针，两者最终朝向相同。

## 执行时序

```text
START：保存初始地图航向及IMU原始角对应关系，快照工作朝向配置
  ↓
保持当前行驶航向，沿相邻地图航点的折线行驶
普通途经点：减速衔接，不原地转向、不等待工作
  ↓
工作点位置到达、平移停稳
  ↓
计算 工作目标航向 = 初始地图航向 + 该工作区偏角（归一化至±180°）
若需要：Chassis_TurnRelative(目标与当前航向之差, 15 rpm)
  ↓
等待转向结束、IMU航向误差/轮速/停稳时间合格
  ↓
ARRIVED → WORK_REQUIRED → WAIT_WORK
树莓派此时才开始扫码/视觉对准/抓取放置
  ↓
正确的 WORK_DONE → 下一批路线
保持本工作区朝向去下一站，不额外转回初始朝向
```

若该站无需改变朝向，直接进入工作等待。转向产生的编码器平移量仍用于地图位置估计；必要时先修正残余位移，再确认到站。中断路线后不会自动恢复。工作超时从进入WAIT_WORK开始计时，不包括尚在转向的时间。

## 配置和函数

`Core/Src/route.c`：

```c
volatile RouteWorkHeadingConfig_t route_work_heading_config = {
    1U,     /* enabled：1启用，0使用原来树莓派每点yaw控制 */
    15U,    /* turn_rpm：工作区转向轮速上限 */
    90.0f,  /* qr_offset_deg */
    -90.0f, /* material_offset_deg */
    90.0f,  /* processing_offset_deg */
    0.0f,   /* storage_offset_deg */
    0.0f    /* home_offset_deg */
};
```

配置在START时快照，运行中改Watch不会改变当前路线。偏角允许−180°～180°，转速1～120 rpm。工作区编号定义在 `Core/Inc/route.h`，必须与树莓派一致。

调用链：

```text
Route_Start()：快照配置、识别任务工作编号、记录travel_yaw
Route_Task() → execute()
  ├─ navigation_yaw()：工作区模式下取上一个工作区朝向
  ├─ start_path()：保持此朝向跟踪地图折线，末点停稳
  ├─ work_yaw()：根据work_id和初始地图航向算本站目标
  ├─ Chassis_TurnRelative()：仅到站后启动工作转向
  └─ 转向/到点均满足后 → Route_OnWork() + WAIT_WORK
Route_CompleteWork()：正常推进下个点，不插入恢复初始朝向动作
```

原来的独立底盘平移、转向API不变，无需新增FreeRTOS任务、串口或中断。

## 树莓派协议与Watch

原帧长度、类型、CRC、选区握手、坐标单位、工作完成格式保持不变。本次任务的原16点路线可原样发送，仍使用工作编号101～108。

**模式识别规则：** enabled=1且路线含任意一个101～108的工作点时，本整条路线启用工作区朝向模式。此时普通点的yaw字段不再触发行驶前转向；行驶保持上次作业朝向，已知工作站按表格到站后转向。混合路线里的未知工作编号在到站后使用该点报文yaw作为作业朝向。若路线完全不含101～108，仍按原来的每点yaw执行。要让树莓派全面接管航向，请在START前关闭本功能；不要让两端同时独立叠加90°偏角。

新增 `route_status.phase=6`：**工作区原地对准中**。树莓派应允许phase6并继续查询，不能把phase6当作完成或故障。此时state仍为RUNNING(2)，WORK_DONE会返回BAD_STATE，不会放行下一段。

只有 `state=3 / phase=4 / WORK_REQUIRED` 表示位置和工作朝向均已准备好。普通点的ARRIVED/POINT_DONE仍不表示停车。工作点的ARRIVED延后至转向结束，避免视觉程序提前工作。

| Watch | 用途 |
|---|---|
| `route_work_heading_active` | 当前路线是否启用了工作区朝向模式 |
| `route_work_heading_config` | 下次START使用的配置 |
| `route_status.phase` | 5连续平移；6工作转向；4等待作业 |
| `route_status.map_yaw_deg` | 当前IMU推算的地图航向 |
| `route_status.target_yaw_deg` | 当前移动/转向目标地图航向 |
| `route_status.point_index / work_id` | 当前路线点/进入等待后的工作编号 |
| `chassis_heading.target_turn_deg / turned_deg / remaining_turn_deg` | 这次原地转向的目标/进度/剩余角 |
| `chassis_heading.yaw_error_deg` | 当前航向误差 |
| `route_status.fault / chassis_motion.fault` | 故障码 |

原16点路线原先只有8批平移。启用本功能后，正常是8批平移加7次工作转向；因此 `chassis_motion.completed_count` 在此仿真中增加15，工作等待仍为8次。暂存第二次→启停区航向相同，无额外转向。

## 联调与验证

工作区旋转会改变摄像头/机械臂和车体的扫掠范围；保持新朝向移动也会改变不对称车体在地图中的占地。树莓派规划器需使用当前朝向对应的车体轮廓，或保守覆盖各朝向的轮廓，并留出机械臂收回后的原地旋转空间。不能继续假定车体全程yaw90°；主控状态里返回的yaw可以用于联调。对准前需确保机械臂处于允许底盘旋转的姿态。

建议先单测二维码到站转向，再连跑二维码→原料→粗加工，观察是否到站后才转、视觉是否收到WAIT_WORK再动作。先低速检查各站位置与摄像头/机械臂对准，最后再提高巡航速度。
